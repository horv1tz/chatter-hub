# Chatter-Hub

Проект мессенджера с поддержкой авторизации, создания чатов, отправки сообщений и файлов, поиска пользователей и управления профилем.

## Стек технологий

- **Backend**: Go (с использованием API и WebSocket)
- **База данных**: PostgreSQL
- **Хранилище файлов**: Minio S3
- **Клиент**: Electron

## Функциональность

1. **Авторизация и регистрация**  
   Пользователь может зарегистрироваться и войти в систему с использованием логина и пароля.

2. **Создание чата с другим пользователем**  
   Пользователь может создавать чат с другим зарегистрированным пользователем.

3. **Отправка сообщений, фото и файлов**  
   Поддержка отправки текстовых сообщений и файлов (например, изображений) в чаты.

4. **Страница профиля**  
   Пользователь может просматривать и редактировать свой профиль (имя, логин).

5. **Удаление сообщений**  
   Возможность удалять сообщения в чате.

6. **Поиск пользователей**  
   Поддержка поиска пользователей по имени или логину.

## Структура базы данных

Проект использует PostgreSQL для хранения данных о пользователях, чатах и сообщениях. Структура базы данных включает:

- **Users**: таблица пользователей (имя, логин, пароль)
- **Chats**: таблица чатов
- **Messages**: таблица сообщений, отправленных в чатах
- **Files**: таблица для хранения информации о файлах, загруженных пользователями

## Запуск Backend

Backend для мессенджера работает через Docker с использованием `docker-compose`. Для запуска необходимо:

1. Создайте файл `.env` в корне проекта и настройте параметры подключения к базе данных и S3:

```env
DB_HOST=localhost
DB_PORT=5432
DB_USER=your_user
DB_PASSWORD=your_password
DB_NAME=your_db
S3_BUCKET=your_bucket
S3_REGION=your_region
S3_ACCESS_KEY=your_access_key
S3_SECRET_KEY=your_secret_key
```

2. Для запуска backend с помощью Docker, выполните команду:

```bash
docker-compose up --build
```

Это создаст контейнеры для PostgreSQL, вашего приложения на Go и других зависимостей, если они указаны в `docker-compose.yml`.

3. Сервер будет доступен по порту, указанному в `docker-compose.yml` или `.env`.

## Запуск Frontend (Electron)

1. Установите зависимости для клиента:

```bash
npm install
```

2. Для запуска клиента выполните:

```bash
npm start
```

Frontend будет доступен в браузере или как отдельное приложение на базе Electron.

## API

| Метод | Эндпоинт | Протокол | Описание | Параметры (тело запроса) | Ответ (успех) | Ответ (ошибка) |
|-------|----------|----------|----------|-------------------------|---------------|----------------|
| POST  | /api/register      | HTTPS | Регистрация нового пользователя | { "username": "string", "password": "string", "name": "string" } | { "message": "Пользователь успешно зарегистрирован" } | 400 Bad Request (неверный формат) |
| POST  | /api/login         | HTTPS | Аутентификация пользователя | { "username": "string", "password": "string" } | { "message": "Успешный вход", "token": "string" } | 401 Unauthorized (неверные учетные данные) |
| GET   | /api/profile/:user_id | HTTPS | Получение профиля пользователя | - | { "user": { "id": "uint", "username": "string", "name": "string" } } | 404 Not Found (пользователь не найден) |
| GET   | /api/chats         | HTTPS | Получение списка чатов пользователя | - | { "chats": [ { "id": "uint", "type": "string", "name": "string" } ] } | 500 Internal Server Error |
| GET   | /api/search        | HTTPS | Поиск пользователей по имени | username (query параметр) | { "users": [ { "id": "uint", "username": "string", "name": "string" } ] } | 400 Bad Request (параметр отсутствует) |
| GET   | /api/ws            | WSS    | Установка WebSocket соединения | - | - | 401 Unauthorized (неверный токен) |
| POST  | /api/message       | HTTPS | Отправка сообщения | { "receiver_id": "uint", "content": "string", "media_url": "string" } | { "message": "Сообщение отправлено", "message_id": "uint" } | 400 Bad Request (неверный формат) |
| POST  | /api/create-chat   | HTTPS | Создание нового чата | { "type": "string", "name": "string", "user_ids": [ "uint" ] } | { "message": "Чат создан", "chat": { "id": "uint", "type": "string", "name": "string" } } | 400 Bad Request (неверный формат) |
| POST  | /api/block-user    | HTTPS | Блокировка пользователя | { "block_id": "uint" } | { "message": "Пользователь заблокирован" } | 400 Bad Request (пользователь не найден) |
| POST  | /api/upload        | HTTPS | Загрузка файла | file (multipart/form-data) | { "message": "Файл успешно загружен", "file_url": "string" } | 400 Bad Request (ошибка загрузки) |
| DELETE| /api/delete-message/:message_id | HTTPS | Удаление сообщения | - | { "message": "Сообщение успешно удалено" } | 404 Not Found (сообщение не найдено) |
| GET   | /api/messages      | HTTPS | Получение списка сообщений | - | { "messages": [ { "id": "uint", "content": "string", "timestamp": "time" } ] } | 500 Internal Server Error |

### Уточнения:
1. **/api/profile/:user_id** — для этого эндпоинта важно, чтобы в запросе был параметр `user_id`, который должен быть числовым идентификатором пользователя.
2. В случае ошибки с загрузкой файла через **/api/upload**, ошибка может быть связана с некорректной загрузкой файла, что нужно уточнить.
3. В случае с **/api/ws**, соединение устанавливается через WebSocket (WSS), и ошибки могут быть связаны с недействительным токеном.
